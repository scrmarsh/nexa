# nexa v0.0.32 alpha — scrolling

Appearance previously placed its long StackPanel directly in the fixed Settings host. It had no ScrollViewer, and the application-wide ScrollBar style forced zero dimensions and disabled hit testing. Seasonal Appearance also omitted the ordinary theme controls. The page now has one physical vertical ScrollViewer, bottom padding, automatic extent measurement and a fixed header/navigation/footer. Native scrollbars have a visible 12-DIP hit target and draggable thumb. Horizontal tracks retain horizontal page commands.

`NexaScrolling` is registered once on Window and ScrollViewer preview wheel routes (the latter also covers popup roots). It ignores handled and Shift-modified input, traverses visual/logical/content parents, and gives the deepest eligible vertical owner the gesture. Only at a boundary does its parent receive that event. Successful handling marks the event handled, preventing duplicate owner movement. Text editors keep native selection and keyboard behavior; focused closed selectors retain deliberate discrete stepping, unfocused closed selectors scroll their page, and open dropdowns scroll their list.

Physical distance is delta / 120 × Windows WheelScrollLines × current font line height (font size × 1.2). The Windows page-scroll setting uses the viewport; zero lines means no movement. One event is capped at a viewport. Logical item panels retain fractional remainders until an item can move. Pending WPF offsets merge same-frame fine deltas into one target; a direction change uses the actual current offset. There is no animation, inertia, timer or per-event dispatcher backlog. Keyboard input, horizontal input and native scrollbar dragging remain under WPF control.

The template retains PART_Track and native command routing rather than implementing dragging. Reference: [official WPF ScrollBar implementation](https://raw.githubusercontent.com/dotnet/wpf/main/src/Microsoft.DotNet.Wpf/src/PresentationFramework/System/Windows/Controls/Primitives/ScrollBar.cs). Regression checks exercise native vertical thumb drag, Page Down and horizontal track paging.

WPF MouseWheelEventArgs does not reliably identify a device. No device-specific heuristic or raw hook was added. Small synthetic deltas and same-frame bursts verify proportional accumulation; conventional 120-delta notches remain responsive and respect the user's system settings. These checks cannot establish physical precision-trackpad feel, OS gesture synthesis, mixed-device behavior or driver-specific acceleration. Physical precision trackpad acceptance is **UNVERIFIED**. Test gentle/rapid/reversing gestures, inner boundaries, open dropdowns, text selection and Shift/horizontal input on actual laptop hardware before release. Real 125%/150% Windows DPI and mixed-monitor transitions also remain open; LayoutTransform fixtures are layout stress tests only.
