# nexa .33 installer and data guide

Use **NexaSetup.exe** for normal installation. It installs for the current Windows account under `%LocalAppData%/Programs/nexa`, registers nexa in Windows Installed Apps and creates a Start menu entry. A desktop shortcut is selected by default. No administrator privileges are required. Publisher is `scrmarsh`; the package is unsigned and makes no verified-publisher claim. The permanent icon is the approved Classic icon.

The executable inside Setup is identical to `nexa-portable.exe`. Updates are retained in both. Installed mode uses verified Setup upgrades so the registered version, uninstaller and shortcuts remain consistent. Portable mode can migrate through Setup with its original executable backed up. Settings → Updates and startup use the same first-run choice, discovery, save gate, 30-second countdown, Restart now and Later flow. A postponed update cannot restart from its old countdown. Disabling automatic installation keeps notices enabled.

Private saves remain in `%LocalAppData%/SessionDashboard`: existing state, SID-scoped preferences/credentials, recordings, history and ecosystem files. They are not moved into Program Files. This matches the user's explicit storage choice and preserves existing portable saves. Open **Files** on Home, or **Settings → Files & sharing**, for Open Data Folder, Open Spaces Folder and Open History Folder. Space exports default to the Windows Documents known folder under `nexa/Spaces`; readable history copies are generated under `nexa/History`. Documents may be redirected by Windows or OneDrive. Exporting session content is optional and can include private notes/transcripts; credentials are excluded. Readable copies do not become a second save database. Refreshing history does not mutate original records. User-exported documents are retained during uninstall.

## Migration and cleanup

Setup checks that nexa is closed, backs up private data and scans Desktop, Downloads and Documents without running candidates. Full local-drive scanning is optional and can take time. Linked paths, inaccessible directories, source repositories and system folders are skipped. Published old copies are identified by embedded identity plus recorded release SHA-256. Cleanup is a visible selected task and can be disabled. Only verified, backed-up executable files are removed after the new application passes startup health. Unrelated files, unknown custom builds and original adjacent saves are retained. The migration report records preserved copies and cleanup failures; a partial cleanup is not presented as deleting every copy on the computer.

Shared private saves normally need no migration. Recognized adjacent workspace saves are validated for the current Windows account, copied with recordings and scoped profile data, and merged without replacing the selected existing Space. Conflicting Space identities become separate imports. Original adjacent data and verified backups remain. Unsupported old data stays in its original folder for recovery. Preparation failures restore authoritative state files from backup; retained migration material is never deleted automatically.

## Repair and uninstall

Rerun the installer to repair missing application files without resetting saves. Upgrades reuse the installation identity/path and shortcut names. A cached copy of Setup is kept for repair and update rollback. Installed updates validate official download size/digest, x64 executable product/version, free disk space, candidate/previous package copies and data backup. After checkpointing, the helper waits for app exit, runs Setup, checks startup and rolls an installed upgrade back using the previous Setup if health fails. A failed first conversion from portable retains the portable recovery backup and reports RecoveryRequired rather than claiming installation success.

Use Windows Installed Apps to uninstall. The default is **keep Spaces, sessions, settings and history**. Choosing **remove all local nexa data** explains recordings, transcripts and local tokens, then requires another confirmation. The recursive removal refuses linked data trees. Cloud content and exported Documents files are not deleted. Silent uninstall keeps data unless both explicit removal parameters are supplied. Errors removing data are reported.

## Builds

The maintained installer is Inno Setup 7.1.1. `tools/Get-InstallerCompiler.ps1` pins the official download SHA-256 and verifies its Authenticode publisher before portable extraction. `tools/Build-Release.ps1` publishes one Windows x64 application, builds Setup, copies the same executable as the portable download, creates a legacy migration launcher and writes SHA256SUMS. Compiler scripts/payloads are checked by version/identity. This is a reproducible workflow; signing timestamps and embedded source hashes mean different source commits need not have identical binary bytes.

`Nexa.exe` on .33 is a compatibility installer launcher for immutable .29/.31 updaters, not a second application feature set. It bundles the verified Setup, checks its hash/identity, accepts the old helper's isolated health mode and opens Setup after restart. Real .24/.26 comparators use the old numbering and can reject canonical .33 before downloading anything; those users need the direct installer once. No metadata edit can patch their existing code. The legacy tags/binaries are preserved.

Native tests use a separate product ID, HKCU registration and application/data/shortcut paths under verification. They do not install into the user's live nexa directory. The prior-version upgrade fixture uses today's installer/application code with synthetic .32 metadata; it is not claimed as a previously released installer.
